# Fish Ecosystem AI в QuietLake

Архитектурное решение для ветки master, 23 ноября 2026 года. Первый прототип следует встроить в существующий runtime-модуль QuietLake. У проекта уже есть серверное озеро, экологические расчёты и специализированный актор рыбы. Главная новая граница проходит между долговечным состоянием особи и временным игровым актором, через который рыбак видит, подсекает и вываживает эту особь.

## Движок и выбор технологий

QuietLake.uproject указывает 5.8. В F:/UE_5.8/Engine/Build/Build.version указана **5.8.4**, changelist 58902052. Штатная проверка Tools/Build.ps1 завершилась Result: Succeeded для QuietLakeEditor Win64 Development. UBT сообщил о режиме совместимости порядка include UE 5.6. Для текущего этапа изменение targets не требуется. Установка 5.9 для этого проекта не подтверждена. Совместимость будущей версии требует повторной сборки и проверки модели на целевой платформе.

| Кандидат | Что проверено локально | Условие применения |
|---|---|---|
| NNE и NNERuntimeORT | В Engine/Source/Runtime/NNE присутствуют NNEModelData.h, NNERuntimeCPU.h и интерфейс CanCreateModelCPU/CreateModelCPU. Дескриптор ORT установлен в Engine/Plugins/NNE. | На этапе ML проверить импорт конкретного ONNX, размеры тензоров, результат CPU-инференса и упаковку runtime под сервер. |

Ни одна из перечисленных ML-технологий не является прямой зависимостью QuietLake.Build.cs. Присутствие файлов движка подтверждает доступность для разработки. Выполнение модели, запуск двух клиентов и сборка отдельного Server target требуют самостоятельных испытаний. Текущий TestNetwork.ps1 использует UnrealEditor-Cmd в режиме -server и два клиентских процесса.

## Контракты интеграции

1. Серверный шаг сначала читает снимок среды и соседей, затем выбирает намерения, разрешает конкурирующие действия и записывает результат. При двух атаках на одну плотву успешное списание возможно один раз. Полученная энергия ограничена фактически съеденной биомассой. Для щуки учитывать укрытие и стоимость броска, для окуня размер и группу, для плотвы доступность корма и угрозу.
2. Передача в модель включает глубину, параметры воды, свет, корм, укрытие, расстояния до добычи и угрозы с признаком наличия, скорость и направление, голод, энергию, признаки особи и память. Версионировать порядок, единицы, нормализацию и список намерений вместе с весами. Исполнитель проверяет допустимость атаки независимо от оценки сети.
3. У особи только одно активное представление. На границах LOD использовать разные пороги входа и выхода. Рыбу на крючке удерживать в L1. Значимые особи сохраняют ID и память даже в L3, остальные переходят в когорты с учётом количества, биомассы и возрастной группы. При материализации списывать соответствующую долю когорты.
4. При захвате рыбы сервер резервирует ID за снастью. Повтор команды или конкурирующая подсечка не дают второй улов. При изъятии записывать событие с уникальным ключом до подтверждения клиенту. После запуска загружать последний целый снимок и воспроизводить последующие события по номеру. Снимок включает календарь, UTC-точку остановки, популяцию, память, когорты, корм, погоду и состояние генератора случайных чисел. Для локального хранилища публиковать снимок атомарной заменой после проверки записи. Повреждение сохранения должно быть видимой ошибкой загрузки. Для простоя применять ограниченный по работе зональный расчёт с настраиваемым пределом и запретом отрицательного интервала.

## Запуск первого прототипа

Из каталога проекта в PowerShell:

```powershell
& 'F:\UE_5.8\Engine\Binaries\Win64\UnrealEditor.exe' .\QuietLake.uproject /Game/Maps/Lake -game -FishEcosystemPrototype
```

F3 в локальном мире показывает ID щуки и текущей добычи (0 означает отсутствие индивидуальной цели), энергию, голод и остаток бентоса в текущей ячейке. Преследование и кормление используют существующие правила рыбы. Начальная группа фиксирована, улов и съеденная добыча не пополняются. Раскладка воспроизводится, исход охоты может различаться между запусками. Два часа на сутки действуют и в обычном режиме.

### Четыре вида в экспериментальном запуске

Прототип заселяет озеро одной щукой, одним окунем, шестью плотвицами и двумя карасями. Для каждого вида Tools/FishTraining/train_species.py обучает сеть оценивать три намерения (перемещаться, кормиться, отдыхать) по результатам шестишаговых синтетических эпизодов. Наблюдения включают голод, энергию, активность, угрозу, укрытие и пищу. Сервер использует веса из FishDecisionWeights.h. У щуки при кормлении работает дополнительная сеть решений о сближении и броске. Координация стаи, реакция на опасность и донное кормление остаются в видовом коде. Модели обучены на игровой функции полезности. Проверка на удержанных примерах характеризует совпадение с этой функцией, а полевую точность ещё предстоит оценивать.

Ориентиры для настройки — [опыты с щукой и растительностью](https://pubs.usgs.gov/publication/1000538), [охота окуня и щуки на стайную плотву](https://lucris.lub.lu.se/ws/files/2802910/624603.pdf) и [наблюдения за атакой и обработкой карася щукой](https://pubmed.ncbi.nlm.nih.gov/28393360/). Длительность игрового интервала после еды и коэффициенты энергетики являются допущениями прототипа.
